# 2026-08-26 · タスク操作履歴

## ✨ 新功能

- **タスクドロワーに「操作履歴」タブを追加**しました（右カラム、`バグ管理` の右隣）。
  誰が・いつ・どのフィールドを追加／変更／削除したかが新しい順に並びます。読み取り専用です。

- **1 回の保存＝1 件**。同時に変えた複数フィールドは 1 件の中に差分行として畳み込まれます。
  「保存を押した回数」と履歴の件数が一致するので、後から経緯を追いやすくなっています。
  差分がゼロの保存（何も変えずに保存を押した）は記録しません。

- **差分の見せ方はフィールドの性質で 3 通り**：
  - 単値（タスク名・進捗・予定/実績期間・工期・上位タスク・所属プロジェクトなど）→ `旧 → 新`。
    旧値はグレーの打ち消し線、日付と数値は桁を揃えて表示します。
  - 集合（担当者・ラベル・サブタスク・先行/後続タスク）→ 矢印ではなく `＋追加` / `－削除` のチップ。
  - 説明（リッチテキスト）→ 共通の前後を削ったインライン差分。`全文を表示` でその場で展開します。
  - ステータスだけは色付きピルで、`未着手 → 対応中` が一目で読めるようにしています。

- **絞り込み**：`ステータス・進捗` / `日程・工期` / `担当者・ラベル` / `説明・その他` で件数付きに絞れます。

- **MCP 経由の更新も同じように残ります**。署名は「MCP」ではなく**操作した本人の名前とアバター色**で、
  画面からの操作と区別できるよう小さな `MCP` バッジが付きます（画面からの操作は無印）。

## 📝 記録するもの / しないもの

記録するのは**タスク内の操作だけ**です。コメント本文・バグ詳細・テストケースの結果は、
それぞれのタブが一次情報を持っているため二重に記録しません。
並び順（ドラッグ）と折り畳みも、UI 操作なので履歴に残しません。
サマリータスクの期間・進捗は rollup による自動計算なので、そもそも差分に現れません。

削除されたタスク自身の履歴はもう開けないため、**サブタスクの削除は親タスク側**に残ります。
依存（FS）の追加・解除は、先行・後続の**両方**のタスクに残ります。

## ⚠️ 挙動変更：MCP 経由のチーム可視域

署名を本人にするため、`/internal/**` でも `X-User-Id`（pm-mcp が MCP トークンから解決して以前から
毎リクエスト送っていたヘッダ）を租户コンテキストに載せるようにしました。これにより、
**MCP 経由のアクセスも画面と同じチーム可視域で絞られます**。

- 以前：API-Key さえあれば租户全量が見えた（ユーザ不明なのでチーム絞り込みが効かなかった）
- 以後：その利用者が owner でなければ、自分の所属チームのプロジェクト／タスクだけ。
  範囲外を触ると 404

これは**収紧**であって緩和ではありません（ヘッダは見える範囲を狭めることしかできない）。
ヘッダのユーザが当該租户に属さない場合は可視域が空になり fail-closed で 404 になります。

stdio モードの pm-mcp は `PM_DEFAULT_USER_ID` が設定されている場合だけ本人署名になります
（未設定なら従来どおり「MCP」名義・チーム絞り込みなし）。

## 🔧 内部

- 新テーブル `pm_task_activity`（追記専用）。差分は `changes` (jsonb) に
  `[{field, from, to, added[], removed[]}]` で保存。担当者名・親タスク名などは
  **記録時点のスナップショット**なので、メンバーが改名・削除されても履歴は正しく読めます。
- 記録はタスク保存と同一トランザクション。マイグレーション未適用のまま静かに履歴だけ欠ける、
  という状態にはならず、保存ごと失敗して気付けるようにしています。
- API：`GET /app/pm/tasks/{id}/activities`。マイグレーション：
  `webapi/schema/migrations/2026-08-26-pm-task-activity.sql`。
- 操作元（`source`）はリクエストパスで判定（`/internal/**` → `mcp`）。ユーザの有無とは独立なので、
  本人署名になっても `MCP` バッジは消えません。
