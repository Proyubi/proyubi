# PM 思维导图（Mind Map）需求文档 / PRD

> 状态：v1（MVP）已评审通过，进入开发
> 负责人：PM（产品） · 实现：pm-api + pm-web
> 关联讨论：对标 ProcessOn 思维导图（参考截图：数据库建模脑图）

## 1. 背景与目标

PM 应用目前覆盖「客户/产品 → 项目/版本 → 任务(WBS) → 甘特/看板/路线图」。
团队在做需求拆解、头脑风暴、产品规划时缺少**自由结构化的脑图工具**，只能借助外部
ProcessOn / XMind，资料散落、无法和项目沉淀在一起。

**目标**：在 PM 应用内提供一个轻量但好用的**思维导图**模块，对标 ProcessOn 思维导图的
核心编辑体验，让团队的脑图与项目资料留在同一系统内。

## 2. 功能定位（已确认）

- **独立文档**：新增顶级菜单「思维导图」。用户可自由创建/管理多张**独立**导图文件，
  租户级隔离。每张导图**可选**关联到某个项目（仅作归类/跳转线索，不强绑定数据）。
- **不做实时协同**（v1 明确不做）：单人编辑模型；整棵节点树作为一份文档保存（jsonb）。
  多人可先后打开编辑，保存采用**版本号乐观锁**，冲突时提示刷新，避免覆盖。

> 该定位决定数据模型为「一张导图 = 一行 `pm_mindmap`，节点树存 jsonb」，菜单为顶级入口。

## 3. 用户故事

- 作为 PM，我能新建一张思维导图，给它命名，并（可选）关联到某个项目，便于归档。
- 作为成员，我能用键盘快速搭脑图：`Tab` 加子节点、`Enter` 加同级、双击改文字、`Delete` 删节点。
- 作为成员，我能折叠/展开分支，专注当前部分；能缩放/平移画布看全局或细节。
- 作为成员，我能给节点上色、切换整图主题，让结构更清晰。
- 作为成员，我编辑后系统自动保存，不用怕丢；离开再回来内容还在。
- 作为成员，我能把导图导出为图片（PNG），贴到周报/文档里。
- 作为团队，多人先后编辑同一张图时，后保存者会被提示「已被他人更新，请刷新」，不会静默覆盖。

## 4. 功能清单（v1 MVP）

### 4.1 导图管理（列表页 `/mindmaps`）
- [x] 导图卡片列表：名称、关联项目、更新时间、节点数预览。
- [x] 新建导图（输入名称 + 可选关联项目）。
- [x] 重命名 / 删除（软删除）/ 修改关联项目。
- [x] 点击卡片进入编辑器 `/mindmaps/:id`。

### 4.2 节点编辑（编辑器 `/mindmaps/:id`）
- [x] 节点：增（子节点 / 同级节点）、删、改（内联编辑文字）。
- [x] 节点备注（note，hover/选中可见，非必填）。
- [x] 折叠/展开有子节点的分支；折叠时显示子节点数角标。
- [x] 节点选中态；单选。
- [x] 键盘快捷键：
  - `Tab` = 加子节点；`Enter` = 加同级节点；
  - `F2` / 双击 = 进入文字编辑；编辑中 `Enter` 提交、`Esc` 取消；
  - `Delete` / `Backspace`（非编辑态）= 删除节点（根节点不可删）；
  - 方向键在兄弟/父子间移动选中（可选增强）。
- [x] 节点上色（调色板）。

### 4.3 画布与视图
- [x] 右向逻辑结构布局（中心主题在左，分支向右展开）—— 对标截图样式。
- [x] 父子贝塞尔连线。
- [x] 平移（空白处拖拽）、缩放（滚轮 / 按钮 / 适应窗口）。
- [x] 主题切换（若干内置配色：经典蓝、暗色、森林绿等）。
- [x] 工具栏：加子/加同级/删除、折叠全部/展开全部、缩放、适应、主题、导出、保存状态。

### 4.4 持久化
- [x] 防抖自动保存（编辑停止 ~800ms 后 PUT）；顶部显示「保存中/已保存/保存失败」。
- [x] 版本号乐观锁：保存带 `version`，服务端不一致返回 409，前端提示刷新。

### 4.5 导出
- [x] 导出 PNG（把当前导图渲染为图片下载）。
- [ ] 导出 SVG / 大纲 Markdown（v2 视情况）。

## 5. 非目标（v1 明确不做）

- ❌ 多人实时协同（多光标/实时同步）—— 需 WebSocket/CRDT，列入 v2 评估。
- ❌ 节点关联到具体任务的双向同步（脑图节点 ⇄ pm_task）。v1 仅导图级别可选关联项目。
- ❌ 富文本节点、图片节点、超链接、关系线（自由连线）、多种结构（鱼骨/组织架构）。v2 候选。
- ❌ 模板库、AI 生成脑图。v2 候选。
- ❌ SQL/DDL 解析建模（截图里那是 ProcessOn 的数据库建模工具，不在本期范围）。

## 6. 数据模型

### 6.1 后端表 `pm_mindmap`

| 列 | 类型 | 说明 |
|----|------|------|
| id | uuid PK | 应用层 `UUID.randomUUID()` |
| tenant_id | uuid | 租户隔离，引用 platform_tenant |
| project_id | uuid null | 可选关联项目，引用 pm_project |
| name | text | 导图名 |
| theme | text | 主题 key（classic/dark/forest…），默认 classic |
| content | jsonb | 节点树 JSON（见 6.2），存为 `{ "root": MindNode }` |
| version | int | 乐观锁版本，每次成功保存 +1 |
| created_at / updated_at / deleted_at | timestamptz | 软删除 |

### 6.2 节点树 JSON（content）

```jsonc
{
  "root": {
    "id": "n_root",
    "text": "中心主题",
    "note": "",
    "color": null,          // 节点强调色 #RRGGBB，null=主题默认
    "collapsed": false,
    "children": [
      { "id": "n1", "text": "分支 1", "children": [] },
      { "id": "n2", "text": "分支 2", "children": [...] }
    ]
  }
}
```

- 节点顺序即数组顺序（无需单独 order 字段）。
- 节点 id 由前端生成（短随机串），仅需在单图内唯一。

### 6.3 前端类型（pm/types.ts）
`MindNode`、`MindMap`（含 root + meta）、`MindMapSummary`（列表项）。

## 7. API（/app/pm/mindmaps）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/app/pm/mindmaps` | 列出当前租户导图（摘要：不含 content） |
| GET | `/app/pm/mindmaps/{id}` | 取单图（含 content + version） |
| POST | `/app/pm/mindmaps` | 新建（name, projectId?, theme?, content?）→ 返回完整图 |
| PUT | `/app/pm/mindmaps/{id}` | 更新（name?/projectId?/theme?/content?/version 必传用于乐观锁）|
| DELETE | `/app/pm/mindmaps/{id}` | 软删除 |

- 统一 `R<T>` 响应；租户由 `TenantContext` 解析。
- 版本冲突：`BizException.of(409, "...")`。

## 8. 验收标准（v1）

1. 侧栏出现「思维导图」顶级菜单，进入可见导图列表。
2. 能新建/重命名/删除导图，能可选关联项目。
3. 编辑器中：Tab/Enter/双击/Delete 四个核心操作正确；折叠/展开正确。
4. 缩放、平移、适应窗口可用；右向布局连线不交叉错乱。
5. 编辑后自动保存，刷新页面内容不丢。
6. 两个标签页先后保存同一张图，后者收到「请刷新」提示而非静默覆盖。
7. 导出 PNG 可下载且内容完整。
8. 三语 i18n（zh-CN / ja-JP / en-US，含 zh-TW）菜单与页面文案齐全。
9. `pm-web`：`npm run tsc` / `npm run lint` 通过；`pm-api` 编译通过。
