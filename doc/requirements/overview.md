# PM 俯瞰ページ（Overview / ダッシュボード）要件定義

> 作成: 2026-06-01 / 担当: PM
> 対象: pm-web 内の PM アプリ（`/projects` 配下）に **横断俯瞰ページを 1 枚新設** する
> ステータス: ドラフト（実装前の要件整理）

---

## 0. 背景と問題

現状の PM アプリは `客户/产品 → 项目/版本 → 任务(WBS) → 成员/依存` というモデルで、画面は
`プロジェクト一覧` `ガント/WBS` `リソース(成員工数)` `顧客マスタ` `ロードマップ` が揃っている。
しかし **「全プロジェクトを横断して状況を俯瞰する入り口」が無い**。個別プロジェクトのガントに
潜って初めて状況が見えるため、

- どの案件が遅れているか / どのタスクが期限を超過しているかが **一覧で分からない**
- マネージャーは複数案件を回しているのに、横断のリスク把握ができない
- メンバーは「自分が今日やるべきこと」「自分の遅延」を毎回ガントを探して確認している

これを解決する **俯瞰ページ 1 枚** を新設する。

## 1. ゴール / 非ゴール

### ゴール（このページが解決すること）
- **G1（最優先）**: 遅延・リスクの早期発見。「いま何がヤバいか」を開いた瞬間に赤信号で示す。
- **G2**: マネージャー（統括）が全案件を横断して健康状態を俯瞰できる。
- **G3**: 各メンバーが「自分の今日/今週やること」「自分の遅延」を 1 画面で把握できる。

### 非ゴール（今回やらないこと / スコープ外）
- 既存のガント / リソース / ロードマップ / 顧客マスタ画面の改修はしない（**俯瞰ページ 1 枚に集中**）。
- 通知（メール/LINE/プッシュ）、コメント機能、工数実績入力などの**新規 PM 機能追加はしない**（別途 Phase で検討、§9 参照）。
- 顧客（社外）向けの公開ビューは今回対象外（利用者は社内の PM とメンバー）。
- AI による示唆・自動リスケは対象外。

## 2. 利用者とビュー

主利用者は **(A) PM/マネージャー（統括）** と **(B) 各メンバー（担当者）** の両方。
役割で見たい粒度が違うため、**1 ページ内にスコープ切替**を置く。

| ビュー | 対象 | 既定表示 | 範囲 |
|--------|------|----------|------|
| 全社俯瞰（全社ビュー） | PM/マネージャー | 管理者ロールで既定 | 全プロジェクト横断 |
| マイビュー（My Tasks） | 各メンバー | 一般メンバーで既定 | 自分が担当のタスクのみ |

- 上部にトグル `[全社俯瞰] [マイビュー]` を置き、誰でも切替可能。
- 既定ビューはログインユーザーの role / pm_member 紐付けで自動選択（紐付けが無ければ全社俯瞰）。

## 3. 情報設計（ページ構成）

```
┌─────────────────────────────────────────────────────────────┐
│ ヘッダー:  PM 俯瞰      [全社俯瞰 | マイビュー]   担当者フィルタ▾ │
├─────────────────────────────────────────────────────────────┤
│ ① リスク信号灯（KPI カード行）  ← クリックで②を絞り込み          │
│  [進行中案件] [遅延案件🔴] [遅延タスク🔴] [今週の期日] [未割当]    │
├─────────────────────────────────────────────────────────────┤
│ ② リスク一覧（このページの主役）                                │
│   リスク種別バッジ + 案件 + タスク + 担当 + 期日 + 遅延日数 + 進捗 │
│   遅延日数の降順。行クリック → 該当ガントへジャンプ              │
├──────────────────────────────┬──────────────────────────────┤
│ ③ 案件ヘルス（案件別サマリ）   │ ④ 今週のマイルストーン         │
│  進捗・期日・遅延数を案件ごと   │  期日接近の▼を時系列で          │
└──────────────────────────────┴──────────────────────────────┘
```

マイビュー時は ① のカードが「自分の」数値に変わり、② が自分担当のタスクのみになる。

## 4. 機能詳細

### ① リスク信号灯（KPI カード）
クリックすると②のリスク一覧が該当種別でフィルタされる（ドリルダウン）。

| カード | 定義 | 色 |
|--------|------|----|
| 進行中案件 | status=active の project 数 | 通常 |
| 遅延案件 🔴 | 「遅延(期限超過)」タスクを 1 件以上含む project 数 | 赤 |
| 遅延タスク 🔴 | リスク種別 overdue(期限超過) の leaf タスク数。進捗遅れ(behind) は含めない | 赤 |
| 今週の期日 | 今後 7 日以内に end を迎える未完タスク/マイルストーン数 | 黄 |
| 未割当 | 直近に着手予定なのに担当未設定の leaf タスク数 | 黄 |

### ② リスク一覧（主役）
- 行 = リスクを持つ leaf タスク（または マイルストーン）。
- 列: `リスク種別` `顧客/案件` `タスク名` `担当(アバター)` `期日(plan)` `遅延日数` `進捗バー`。
- 既定ソート: 遅延日数 降順 → 期日 昇順。
- フィルタ: リスク種別、担当者、顧客/案件。
- 行クリック: `/projects/:projectId/gantt?taskId=:taskId` へ遷移し、該当行をハイライト
  （ガント側に `taskId` クエリ受け口を 1 箇所だけ追加。これはスコープ内の最小改修とする）。
- 空状態: 「遅延・リスクはありません 🎉」を明示（“健全”が分かる状態）。

### ③ 案件ヘルス（案件別サマリ）
- 案件ごとに 1 行: 案件名 / 進捗バー（project.progress）/ 期日 / 遅延タスク件数バッジ / ステータス Tag。
- 期日超過案件は行を赤系で強調。クリックで該当ガントへ。

### ④ 今週のマイルストーン
- type=milestone かつ end が今後 14 日以内（未完）を時系列リスト表示。
- 期日まであと N 日、超過なら「N 日超過🔴」。

## 5. リスク判定ルール（要・実装合意）

`today = システム日付`。leaf（type=task）と milestone を対象、summary は集計のみ。

| 種別 | 判定式 |
|------|--------|
| **遅延 (overdue)** | `progress < 100` かつ `end < today` |
| **進捗遅れ (behind)** | `today ∈ [start, end]` かつ `progress < 期待進捗 − 15pt`<br>`期待進捗 = round((today−start)/(end−start) × 100)`（0–100 にクランプ） |
| **依存ブロック (blocked)** | 後続タスクの predecessor に未完（progress<100）があり、後続の `start ≤ today+3日`（着手予定が迫る）→ §6 のデータ制約あり |
| **期日接近 (due-soon)** | `progress < 100` かつ `0 ≤ end − today ≤ 7日`（マイルストーンは 14 日） |
| **未割当 (unassigned)** | leaf かつ `assigneeIds = []` かつ `start ≤ today+7日` |

- 閾値（behind の 15pt、due-soon の 7/14 日、unassigned の 7 日、blocked の 3 日）は**設定可能な定数**として実装し、後で調整できるようにする。初期値は上表。
- 優先度（複数該当時のバッジ表示順）: overdue > blocked > behind > due-soon > unassigned。

## 6. データ取得と後端改修

### MVP は既存 API で構築可能
- `GET /app/pm/workload`（memberId なし）= 全 leaf/summary/milestone を計画・実績・進捗・担当・案件/顧客名つきで返す → ①②③④の大半をフロント集計で算出可能。
- `GET /app/pm/projects` = 案件ヘルス・進捗。
- `GET /app/pm/members` = 担当アバター/フィルタ。
- マイビューは `getWorkload(memberId)` で単人モードを使用、または全件をフロントで絞る。

### 唯一の制約 = 依存ブロック
- workload は dependency を返さないため「依存ブロック」だけ算出できない。対応案:
  - **MVP**: 依存ブロックを除外（残り 4 種別で十分に価値が出る）。
  - **Phase 2**: 後端に集約 API を 1 本追加し、サーバ側でリスク計算（推奨）。
    - 案: `GET /app/pm/overview?scope=all|me` → `{ kpis, riskItems[], projectHealth[], milestones[] }`
    - サーバ集計の利点: リクエスト 1 本、リスク計算ロジックを `TaskRollupService` と同居で一元管理、依存ブロックも算出可。
- 最小改修: ガントに `?taskId=` で該当タスクをハイライトする受け口（②の行クリック遷移用）。

## 7. 遷移・操作
- KPI カード → ②をフィルタ（同一ページ内）。
- リスク行 / 案件ヘルス行 → 該当ガント（`taskId` 付き）。
- `/` のリダイレクト先を `/projects`（一覧）からこの俯瞰ページへ変更するか要検討（§10）。
- ナビ（サイドバー）に「俯瞰 / 概览」を PM ブロック先頭へ追加。

## 8. 横断要件
- **i18n**: zh-CN / en-US / ja-JP の 3 言語（既存 locales に追記）。UI ラベルは日本語が基準。
- **権限**: `access: canAccessMenu`。マイビューは pm_member 紐付け前提（未紐付けは全社俯瞰のみ）。
- **状態**: ローディング（Spin）、エラー（既存 request の統一 toast）、空状態（リスク 0 件＝健全表示）。
- **性能**: 全件 workload 取得は案件規模が小さい想定で許容。肥大化したら Phase 2 集約 API へ。
- **レスポンシブ**: PC 優先。①は折返し、②は横スクロール許容。

## 9. リリース段階

| Phase | 内容 | 状態 |
|-------|------|------|
| **MVP** | 全社/担当者切替・KPI・リスク一覧(overdue/behind/due-soon/unassigned)・案件ヘルス・今週マイルストーン。既存 API のみ。ガントへ `taskId` 遷移。 | ✅ 完了 |
| **P2** | 後端 `GET /app/pm/overview?scope=all\|me` 集約（`PmOverviewService`）。**依存ブロック**算出、**未割当**も全タスク評価で正しく算出。マイタスクはログインユーザー→`pm_member` をサーバ解決。リスク判定はサーバに一元化（フロント `risk.ts` は廃止）。 | ✅ 完了 |
| **P3（別スコープ）** | 通知（期日前アラート / LINE）、コメント、工数実績、顧客向け公開ビュー、AI リスク示唆。`/` 既定ホーム化（見送り中）。 | 着手中（コメント ✅：タスク単位の `pm_comment`、`/app/pm/tasks/{taskId}/comments` ＋ `/app/pm/comments/{id}`、編集弾窗下部に表示。残り：通知 / 工数実績 / 顧客公開ビュー / AI 示唆）。 |

## 10. 意思決定の記録
1. **ホーム化**: 当面**変更しない**（`/` → `/projects` のまま）。P3 で再検討。
2. **マイタスクの本人解決**: `TenantContext.getUserId()` → `pm_member.userId` 一致でサーバ解決。未紐付け時は `meMemberId=null` を返し、フロントは「PM メンバー未登録」案内を表示。
3. **リスク閾値**: §5 の初期値（behind 15pt / due-soon 7・14日 / unassigned 7日 / blocked 3日）を採用。`PmOverviewService` の定数で調整可。
4. **依存ブロック**: P2 でサーバ集約 API として実装済（FS 依存・前序未完 & 着手 3 日以内）。
5. **「遅延」の定義（2026-06-11 変更）**: 「遅延タスク/遅延案件」のカウントは **overdue(期限超過 = end < today) のみ** とする。当初は overdue+behind を合算していたが、`本日`/`あと N 日`/`—` の行まで「遅延」に数えられて直感に反するため、behind(進捗遅れ) はカウントから除外（リスク一覧には引き続きバッジ表示）。`PmOverviewService` の `isDelay` で一元管理。
